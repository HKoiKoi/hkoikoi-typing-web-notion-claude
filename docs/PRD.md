# 노션 타이핑 연습 MVP PRD

## 1. 개요

**문제**: 타이핑 연습용 본문(성경 한 장, 애국가, 영어 글 등)을 직접 관리하고 싶지만, 기존 타이핑 사이트는 본문을 마음대로 추가·편집할 수 없다. 노션은 이미 쓰는 도구라 본문을 모으기 편하다.
**목표**: 노션 데이터베이스에 등록한 한국어/영어 여러 줄 본문(장·곡 단위)을 웹에서 불러와 한 줄씩 따라 치게 하고, 글자별 실시간 판정과 결과 요약(정확도, 소요 시간, 타수/WPM)을 제공한다.
**사용자**: 노션으로 본문을 관리하는 본인 1인(로그인 없음, 단일 사용자).

**용어**: Passages DB의 한 행을 **예문**(Passage)이라 부르고, Lines DB의 한 행을 **줄**(Line)이라 부른다. 예문은 여러 줄로 이루어지며, 줄 하나가 타이핑의 한 단위다. (예: "창세기 1장" = 31줄, "애국가" = 절·후렴 단위 여러 줄)

### 성공 기준 (측정 가능)
| # | 기준 | 측정 방법 |
|---|------|----------|
| S1 | 노션에 예문을 추가하거나 본문을 고치면 재검증 주기 후 앱에 반영된다 | 노션에서 행 추가/본문 수정 → 5분 경과 후 새로고침 두 번(첫 새로고침은 이전 데이터를 보여주며 재검증을 시작하고, 갱신본은 그다음 요청부터 보임. stale-while-revalidate) |
| S2 | 한글 조합 중 입력이 오판정(깜빡이는 틀림 표시, 중복 글자, 입력 누락) 없이 동작한다 | 수동 시나리오: 겹받침(닭, 읽), 이중모음(왜, 의), 빠른 연타 입력 각 5줄 통과 |
| S3 | 입력 후 화면 반영이 체감 지연 없이 이뤄진다 | 일반 노트북 기준 키 입력 → 표시 갱신 100ms 이내(개발자 도구 Performance로 확인, 본문 30줄 이상 예문) |
| S4 | 노션 토큰이 클라이언트 번들/네트워크 응답에 없다 | 빌드 결과 및 브라우저 네트워크 탭에서 토큰 문자열 검색 0건 |
| S5 | 예문 선택 → 전체 줄 완료 → 결과 → 다음 예문까지 막힘 없이 이어진다 | 창세기 1장(31줄) 완주 E2E 1회 통과 |
| S6 | 노션 오류·빈 DB 상황에서 빈 화면 대신 안내 화면이 나온다 | 토큰 오류/빈 DB/네트워크 오류 각각 재현 |
| S7 | 줄 전환과 자동 스크롤이 동작한다 | 31줄 예문에서 현재 줄이 항상 화면 안에 보이고, 마지막 줄 Enter 시 결과 화면 진입 |

## 2. 사용자 여정

```
1. 예문 목록
   ↓ 예문 카드 클릭 (언어/난이도/분류/태그 필터로 좁힌 뒤 선택)
2. 타이핑 화면 (전체 본문 표시, 현재 줄 강조)
   ↓ 첫 글자 입력 시 타이머 시작
   ↓ 현재 줄을 끝까지 일치하게 입력 → Enter → 다음 줄로 이동(자동 스크롤)
   ↓ … 마지막 줄을 일치하게 입력하고 Enter → 종료
3. 결과 화면 (타이핑 화면 내 결과 뷰)
   ├─ [다음 예문] → 현재 필터 목록의 다음 예문 타이핑 화면 (마지막이면 예문 목록). 필터는 URL 쿼리로 전달(4장)
   ├─ [다시 도전] → 같은 예문 타이핑 화면 (초기화)
   └─ [목록으로] → 예문 목록

예외: 노션 조회 실패 → 오류 화면 → [다시 시도] → 예문 목록
      예문 0건 → 빈 상태 → 노션 DB 확인 안내
      존재하지 않는 예문 접근 / 본문이 비어 있는 예문 → 오류 화면 → 예문 목록
```

## 5. 데이터 모델

### 노션 DB 구조: 데이터베이스 두 개 (사용자가 직접 구성, 읽기 전용)
- **Passages DB**: 행 하나 = 예문 한 편(창세기 1장, 애국가, 영어 글 등). 책·장별로 DB를 나누지 않는다. 성경 외 예문도 넣을 예정이라, 책마다 DB와 data source ID를 두면 연동이 복잡해진다. 단일 Passages DB에서는 `Category`와 `Order` 프로퍼티로 같은 묶음 효과를 얻는다. 이 DB의 페이지 본문은 비워 둔다.
- **Lines DB**: 행 하나 = 예문의 줄 한 개. `Passage` 관계로 소속 예문을 지정하고 `Line Number`로 순서를 정한다. 페이지 본문(블록)은 읽지 않는다.
- **본문을 Lines DB로 두는 이유**: 줄 순서(`Line Number`)와 라벨(`Label`)을 속성으로 명시하므로 블록 타입 판별, 소프트 줄바꿈 분리, 괄호 정규식 같은 파싱 규칙이 필요 없고, 관계 필터와 정렬이 적용된 줄을 쿼리 한 번(최대 100행)으로 받는다. 대신 줄마다 행을 만들어야 하므로 입력은 CSV import를 권장한다.
- 프로퍼티 이름과 select 옵션 값은 영어이며 아래 표와 정확히 일치해야 한다(UI 문구는 한국어).

**Passages DB**

| 프로퍼티명 | 노션 타입 | 필수 | 앱 필드 | 비고 |
|-----------|-----------|------|---------|------|
| Title | title | O | title | 예: "Genesis 1", "National Anthem" |
| Language | select (`ko` / `en`) | O | language | 그 외 값은 해당 행 제외(로그만) |
| Category | select | X | category | 예: Genesis, National Anthem, English Text. 없으면 "기타"(UI 표시 문구) |
| Order | number | X | order | 같은 분류 안 정렬(장 번호 등). 없으면 `Title` 순 |
| Difficulty | select (`Easy` / `Medium` / `Hard`) | X | difficulty | 없으면 미지정 |
| Tags | multi_select | X | tags | 없으면 빈 배열 |
| Enabled | checkbox | X | enabled | `enabled === false`인 행은 클라이언트 매핑에서 제외(서버 필터 사용 안 함). 프로퍼티 없으면 전부 사용 |

**Lines DB**

| 프로퍼티명 | 노션 타입 | 필수 | 앱 필드 | 비고 |
|-----------|-----------|------|---------|------|
| Text | title | O | line.text | 타이핑할 줄 내용. 정규화 후 비면 행 제외 |
| Passage | relation → Passages | O | (쿼리 필터) | 소속 예문. 쿼리 시 `relation.contains = 예문 page id`로 필터 |
| Line Number | number | O | (정렬) | 1부터 시작하는 줄 순서. 비어 있으면 행 제외(로그만) |
| Label | rich_text | X | line.label | 줄 앞 배지로만 표시, 판정 제외. 예: `1절`, `후렴`, 창세기 절 번호 |

입력 예시 (창세기 1장, 절 번호·각주는 `Text`에 넣지 않고 필요하면 `Label`에 넣는다):

| Passage | Line Number | Label | Text |
|---|---|---|---|
| Genesis 1 | 1 | 1 | 태초에 하나님이 천지를 창조하시니라 |
| Genesis 1 | 2 | 2 | 땅이 혼돈하고 공허하며 흑암이 깊음 위에 있고 하나님의 신은 수면에 운행하시니라 |
| Genesis 1 | 3 | 3 | 하나님이 가라사대 빛이 있으라 하시매 빛이 있었고 |
| … | … | … | … (31줄) |

애국가 예시 (후렴은 줄을 나눠 입력):

| Passage | Line Number | Label | Text |
|---|---|---|---|
| National Anthem | 1 | 1절 | 동해물과 백두산이 마르고 닳도록 |
| National Anthem | 2 | | 하느님이 보우하사 우리나라만세 |
| National Anthem | 3 | 후렴 | 무궁화 삼천리 화려강산 |
| National Anthem | 4 | | 대한사람 대한으로 길이 보전하세 |
| … | … | … | … (4절까지 16줄) |

앱 내부 타입(개념):
```
PassageSummary { id(노션 page id), title, language: 'ko'|'en', category, order?, difficulty?: 'Easy'|'Medium'|'Hard', tags[] }   // 목록용(Passages 프로퍼티만)
Passage = PassageSummary & { lines: Line[] }                                                          // 타이핑용(Lines DB 행 포함)
Line { text, label? }                                                                                 // label: Label 속성, 판정 제외
TypingResult { passageId, accuracy, elapsedMs, cpm, wpm, mistakes, lineCount }                       // F011에서만 localStorage 저장
PassageResult<T> = { ok: true, data: T } | { ok: false, kind: 'config' | 'transient' | 'notFound' | 'empty' }   // 조회 결과(6장 오류 처리)
```
매핑 규칙: 프로퍼티는 이름으로 접근, 응답의 삭제 여부는 `in_trash` 필드만 사용, 타입이 다르거나 필수값이 비면 해당 행을 건너뛴다. Lines 행은 7.2 정규화를 적용해 `Line.text`/`Line.label`로 저장하며, 정규화 후 `Text`가 비는 행은 버린다. 줄이 0개면 "본문 없음" 오류로 처리한다.

## 6. 노션 연동 명세

- **목록 조회**: 공식 SDK(`@notionhq/client`)의 `dataSources.query`(`POST /v1/data_sources/{id}/query`)로 Passages DB의 프로퍼티만 가져온다. 환경 변수: `NOTION_TOKEN`, `NOTION_DATA_SOURCE_ID`(Passages), `NOTION_LINES_DATA_SOURCE_ID`(Lines) (모두 서버 전용, `NEXT_PUBLIC_` 접두사 금지, 로컬은 `.env`). `@notionhq/client`는 `5.27.0`으로 정확히 고정해 설치했다. API 버전은 SDK 기본값(`2025-09-03`)을 쓰며, `2026-03-11`로 올려도 읽기 전용 앱이라 영향은 거의 없다. data source ID는 노션 DB 설정의 "Manage data sources" → "Copy data source ID"로 얻으며 DB ID와 서로 바꿔 쓸 수 없다. 두 DB 모두 통합(Integration)에 연결해야 한다. 조회 시 `filter_properties`로 필요한 프로퍼티만 받는다.
- **본문 조회**: 타이핑 화면 진입 시 해당 예문의 줄을 Lines data source에서 `dataSources.query`로 가져온다. 필터는 `{ property: "Passage", relation: { contains: <예문 page id> } }`, 정렬은 `Line Number` 오름차순이며, `filter_properties`로 `Text`/`Line Number`/`Label`만 받는다. `has_more`/`next_cursor`로 전부 수집한다(한 번에 최대 100개). 목록 조회에서는 줄을 읽지 않는다. 페이지 본문 블록(`blocks.children.list`)은 사용하지 않는다.
- **행 → 줄 변환**:
  - `Text`(title)의 plain text를 이어 붙여 7.2 정규화를 적용하고, `Label`(rich_text)의 plain text도 같이 정규화한다(비면 라벨 없음).
  - 정규화 후 `Text`가 빈 행, `Line Number`가 빈 행, 삭제된 행(`in_trash`)은 건너뛰고 로그를 남긴다.
  - 쿼리 정렬 결과를 `Line Number` 기준으로 한 번 더 안정 정렬하며, 같은 번호가 중복되면 경고 로그만 남기고 응답 순서를 유지한다.
- **페이지네이션**: 목록과 줄 모두 SDK의 `iteratePaginatedAPI`/`collectPaginatedAPI`를 사용한다(SDK README 예제로 확인됨).
- **필터/정렬**: 목록 쿼리에는 서버 필터를 걸지 않는다. `Enabled`를 포함해 분류·언어·난이도·태그 필터는 전체를 가져온 뒤 클라이언트(매핑 단계)에서 처리한다(예문 수백 건 이하 가정). 정렬은 `Category` → `Order` → `Title`. 서버 필터는 줄 쿼리의 `Passage` 관계 필터만 쓴다.
- **캐싱/재검증** (Next.js 16.3.8 문서 `node_modules/next/dist/docs/` 확인 완료):
  - `next.config.ts`에 `cacheComponents: true`를 켜고, 조회 함수를 서버 전용 모듈로 분리해 `use cache` + `cacheLife` + `cacheTag`로 캐싱한다. `reactCompiler`와는 독립이다.
  - 5분 재검증은 `cacheLife({ revalidate: 300 })`으로 표현한다(`stale`, `revalidate`, `expire` 직접 지정 가능. 내장 `minutes` 프로파일은 revalidate 1분이라 맞지 않음).
  - 태그: 목록은 `passages`, 줄은 `passage-{id}`. 수동 갱신은 `revalidateTag(tag, 'max')`(문서의 권장 형태, 두 번째 인자 필수)로 하고, 서버 액션에서 즉시 반영이 필요하면 `updateTag`를 쓴다. "새로고침" 버튼은 선택.
  - 줄은 예문별로 한 번 조회 후 캐시하며, 같은 예문을 다시 열어도 노션을 다시 호출하지 않는다.
  - `cacheComponents: true`에서는 `params`/`searchParams`가 런타임 API이므로 `/passages/[id]` 본문은 `<Suspense>` 안에서 렌더하고 `loading.tsx`를 둔다. 목록 페이지는 빌드 시 프리렌더되어 `next build` 중 노션을 호출하므로, 빌드 환경에도 토큰과 data source ID 두 개를 설정해야 한다.
- **오류 처리**: `isNotionClientError`와 `APIErrorCode`로 분기. 프로덕션에서는 서버 컴포넌트에서 던진 오류 메시지가 가려지므로 `error.message`로 분기하지 않는다.
  - 조회 함수는 `PassageResult<T>`(5장)를 반환하고, 페이지(서버 컴포넌트)가 `kind`에 따라 `EmptyState`를 렌더한다. `error.tsx`는 예상 밖 오류용 최후 방어선으로만 둔다.
  - `use cache` 함수는 성공 데이터만 반환하고 실패하면 throw한다(오류 결과가 5분간 캐시되는 것을 방지). try/catch로 `PassageResult`로 분류하는 일은 캐시 밖의 래퍼에서 한다.
  - `unauthorized`/`restricted_resource`/`object_not_found` → `config`(토큰, 두 DB의 통합 연결, ID 확인 안내)
  - `rate_limited`, 5xx 계열, 타임아웃 → `transient` + 재시도. SDK가 `rate_limited`/500/503/529를 기본 2회 자동 재시도한다. 캐시된 이전 데이터가 있으면 표시한다(재검증 실패 시 기존 캐시 항목이 유지되는지는 구현 중 검증, 10장)
  - 환경 변수 누락(Lines data source ID 포함) → `config`
  - 예문 ID가 캐시된 목록(`Enabled` 해제 포함)에 없음 → `notFound`, 해당 예문의 줄이 0개 → `empty`
  - 행 단위 파싱 실패는 전체 실패로 만들지 않고 건너뜀
- **토큰 비노출 제약**: 토큰은 서버 모듈에서만 읽고 클라이언트 컴포넌트로는 가공된 `PassageSummary[]`/`Passage`만 전달한다. 서버 전용 모듈(`src/lib/notion/*`와 서버 래퍼)에는 첫 줄에 `import "server-only"`를 둔다(`server-only@0.0.1` 도입 확정).

## 7. 타이핑 판정 로직

### 7.1 비교 단위
문자열을 NFC 정규화 후 코드 포인트 배열(`Array.from`)로 분해해 글자 단위로 비교한다. 한글은 완성형 음절 1글자 = 1단위. 판정은 **현재 줄 하나**에 대해서만 수행한다. 인덱스 i의 입력 글자와 줄의 글자가 같으면 맞음.

### 7.2 줄 정규화와 라벨 (Lines DB 로드 시)
1. `Text`와 `Label`에 NFC 정규화, 탭은 공백으로 치환, 줄 내부 연속 공백은 1칸으로 합치고 양 끝 공백 제거. 정규화 후 `Text`가 비면 그 줄은 버린다.
2. 라벨은 `Label` 속성 값을 그대로 쓴다(예: `1절`, `후렴`, 창세기 절 번호 `1`). 화면에는 배지로만 표시하고 타이핑 대상에서 제외한다. `Text` 맨 앞의 괄호(예: `(Note: …)`)는 라벨로 분리하지 않고 본문 글자로 취급한다. 정규화 후 `Label`이 비면 라벨 없음.
3. 절 번호와 각주 표기는 `Text`에 넣지 않는다는 전제이므로 별도 제거 규칙을 두지 않는다. 필요하면 `Label`에 넣고, `Text`에 있으면 본문 글자로 취급된다.
4. 공백은 일반 글자와 동일하게 판정하며 틀린 공백은 시각적으로 구분(배경색 표시). 스마트 따옴표/긴 대시 등 특수문자는 그대로 비교(대소문자 구분, 자동 치환 없음).

### 7.3 줄 전환 (Enter)
- 입력은 현재 줄 하나에 대한 버퍼 하나이며, 줄이 바뀌면 버퍼를 비운다.
- **Enter 동작**: 입력이 줄 전체와 일치할 때만 다음 줄로 이동한다. 일치하지 않으면(부족하거나 틀림) 이동하지 않고 "줄이 일치하지 않습니다" 표시(짧은 강조 효과)로 알린다. 입력창에 줄바꿈 문자는 들어가지 않는다.
- **조합 중 Enter는 보류**: 조합 중(`isComposing || keyCode === 229`)에 Enter가 오면 줄 전환을 바로 하지 않고 `pendingEnter = true`만 기록한다. `compositionend` 직후 확정된 값으로 줄 일치를 판정해, 일치하면 바로 전환하고 `pendingEnter`를 해제한다. 조합 중이 아닐 때의 Enter는 즉시 판정한다. 이벤트 순서에 의존하지 않고 Enter 한 번으로 동작해야 한다. 지원·검증 대상 환경은 Chrome + macOS 한글 IME이다(Safari·Firefox는 검증하지 않음, 10장 12).
- **Chrome(macOS) 실측**: 조합 확정 Enter 한 번에 keydown이 두 번 온다. `keydown Enter(isComposing=true, keyCode=229)` → `compositionend` → `keydown Enter(isComposing=false, keyCode=13)`. 두 번째 Enter는 첫 Enter가 이미 줄을 전환해 입력창이 비어 있는 상태에서 오므로, 그대로 즉시 판정하면 불일치로 오판한다. 따라서 보류된 Enter를 `compositionend`에서 판정한 직후의 비조합 Enter 1개는 무시하고(`suppressEnter`), Enter keyup·새 조합 시작·조합 중 Enter에서 무시 상태를 해제한다.
- **종료**: 마지막 줄에서 일치 상태로 Enter를 누르면 종료하고 결과 뷰로 이동한다.
- **자동 스크롤**: 줄 전환 시 새 현재 줄이 본문 영역 안(가능하면 세로 중앙 부근)에 오도록 스크롤한다. 사용자의 `prefers-reduced-motion` 설정이 있으면 부드러운 스크롤을 끈다.
- 이전 줄로 돌아가기는 지원하지 않는다. 완료한 줄은 수정할 수 없다.

### 7.4 한글 조합 처리
- 입력 요소에 `compositionstart/compositionend`를 연결해 `isComposing` 상태를 추적하고, 입력값은 input의 `onChange`에서 읽는다(조합 중 값에는 조합 중인 글자가 마지막에 포함됨).
- 조합 중이 아닌 확정 구간(마지막 글자 제외)은 즉시 맞음/틀림 판정.
- 조합 중인 마지막 글자는 "조합 중" 상태로 중립 표시(틀림 색 사용 금지). 단, 줄 글자를 자모 분해(NFD)한 것의 접두가 아니면 "조합 중 불일치"로 약하게 경고할 수 있으며(선택), 최종 판정은 `compositionend` 이후.
- 조합 중에는 오타 횟수와 진행도를 갱신하지 않는다. `compositionend` 시점에 확정 글자로 갱신.
- 영어 입력에는 조합이 없으므로 `onChange`마다 즉시 판정.
- 마지막 글자가 조합 중일 때 Enter는 즉시 줄 완료로 처리되지 않고 보류되었다가 조합 확정 후 판정된다(7.3).
- 입력 요소는 `autocomplete/autocorrect/autocapitalize/spellcheck`를 꺼 브라우저 보정을 막는다.
- **조합 중 `value` 미변경(D10)**: 입력은 controlled를 유지하되 조합 중에는 `onChange`의 값을 그대로 상태에 반영하고 변형하지 않는다. 조합 중 `value`를 바꾸면 자모가 합쳐지지 않고 키마다 새 조합이 시작되어 음절이 만들어지지 않는다(Chrome·macOS 실측). 줄 일치 판정에는 `compositionend` 시점의 입력값을 쓴다.
- **조합 경계(Chrome·macOS 실측)**: `compositionstart/end`는 음절마다 오지 않는다. 단어 끝 스페이스는 조합을 확정하며 확정 데이터에 공백이 포함된다(`"읽 "`). 단어 안에서는 받침이 붙을 수 없는 자음이 올 때(`닭`+`ㅇ`) `compositionend`와 `compositionstart`가 1ms 안에 연달아 발생한다.

### 7.5 입력 길이와 붙여넣기
붙여넣기는 차단한다. 입력이 현재 줄 길이를 넘으면 초과분을 잘라내되, 조합 중에는 input의 value를 강제로 바꾸지 않고(IME 조합이 끊기거나 글자가 중복될 수 있음) `compositionend` 이후에 적용한다. 조합 중에 넘친 글자는 "초과" 상태로 표시만 한다.

### 7.6 지표 계산
- 시간: 첫 입력 시점 ~ 마지막 줄 Enter 시점(`performance.now()`). 줄 사이의 쉬는 시간도 포함한다.
- 정확도(%) = (1 − 누적 오타 수 ÷ 누적 입력 글자 수) × 100. 오타 수는 글자가 확정될 때 줄과 다르면 +1 (백스페이스 후 재입력도 입력 수로 계산). 전체 줄을 합산한다.
  - **집계 명세(순수 함수)**: 이전 확정 문자열과 새 확정 문자열을 비교해, 새로 추가·변경된 위치의 글자만 입력 수와 오타 수에 더한다. 같은 위치의 같은 글자를 중복으로 세지 않으며, 백스페이스 후 다시 입력한 글자는 새 입력으로 센다. 음절마다 `compositionend`가 발생한다고 가정하지 않고 확정 문자열의 차이로만 계산한다.
- 타수(CPM) = 전체 줄 글자 수(라벨·줄 사이 Enter 제외) ÷ 소요 분. 한글은 완성 음절 기준(자모 키 입력 수 아님). 화면 라벨은 "타수(음절/분)"처럼 단위를 명시한다.
- WPM = (전체 줄 글자 수 ÷ 5) ÷ 소요 분 (영어 관례 5자=1단어, 한글도 같은 식 적용)
- 화면의 실시간 타수·정확도는 같은 식으로 지금까지의 값을 표시한다.

### 7.7 백스페이스/오류 정책
백스페이스 허용(현재 줄 안에서만). 틀리게 입력해도 입력은 계속 진행되며 틀린 글자는 틀림 표시로 남는다. 틀림이 하나라도 있으면 Enter로 이동할 수 없으므로 수정해야 다음 줄로 넘어갈 수 있다.

### 7.8 성능
판정은 현재 줄의 입력값 전체를 매 입력마다 재계산하는 순수 함수로 구현(줄 하나는 수십~수백 자 규모). 완료한 줄은 정적 렌더링한다. React Compiler가 활성화되어 있으므로 수동 메모이제이션 불필요.

## 8. 비기능 요구

- **성능**: 입력 → 표시 갱신 100ms 이내(S3). 목록은 서버 렌더링 후 필터는 클라이언트 처리. 노션 호출은 캐시 미스 때만. 30줄 이상 본문에서도 현재 줄만 재렌더링되도록 완료한 줄과 남은 줄을 분리해 렌더링한다.
- **접근성**: 판정 구분을 색에만 의존하지 않음(밑줄/취소선/배경). 숨은 입력창에 `aria-label`, 현재 줄에 `aria-current="true"`, 줄 완료·결과만 `aria-live`로 안내(글자마다 낭독 금지). 키보드만으로 목록 선택 → 타이핑 → 결과 버튼 조작 가능. 포커스 링 유지.
- **반응형**: 모바일/태블릿/데스크톱 지원. 예문 줄은 줄바꿈되며 모바일에서 입력창 포커스 시 가상 키보드에 가리지 않게 현재 줄이 보이도록 스크롤한다. 물리 키보드 데스크톱을 주 대상으로 하고 모바일은 사용 가능한 수준.
- **다크모드**: next-themes(class 방식)와 기존 ThemeToggle 활용. 맞음/틀림/현재 글자 색은 `globals.css` 테마 토큰으로 정의하고 라이트/다크 대비 4.5:1 이상.
- **언어**: UI 문구 전부 한국어.
